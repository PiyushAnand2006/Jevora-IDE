# Known limits

* **Laya is not validated — and zero-shot numbers are now measured.** The real weights (`convaiinnovations/laya`, CPU) ran through the eval harness (2026-10-31, seed dataset): verification accuracy **34.4%** with **65.6% false confirms** — near-random, matching the upstream warning — while routing scored 96.4% at p95 ≈ 2.8 s. The promotion gate validates it for nothing, and the RulesEngine veto (D6) blocks its confirmations. To validate: collect real labelled decisions from actual runs (`POST /api/decisions/{id}/label`, escalation answers), fine-tune/calibrate (D22), re-run `python -m backend.decision.eval` (needs `DATABASE_URL` for SQLite or Postgres; on machines where `TORCHINDUCTOR_CACHE_DIR` points into an unwritable location, redirect it), then `--promote`. The seed dataset is circular (D23) and does not count as validation.
* **Jev is untested live.** It is waitlisted, and its request format is modelled on Laya's `system_one`. It is tested with a mock transport only.
* **Native computer-use adapters** (OpenAI, Claude, Gemini) are tested against recorded API shapes, not live keys. The generic vision-JSON adapter is tested end to end. Docker-mode Playwright (`SCREEN_BROWSER=docker`) is implemented but untested (no Docker in the development sandbox).
* **Real local model quality.** The full flow is verified with a scripted mock LLM and by unit tests; a real Build run through a local model (e.g. Ollama `llama3.2`) has not been done on this machine — Ollama is not installed. Small local models may struggle with tool calling.
* **Sandbox network allow-list is proxy-level.** `SANDBOX_NETWORK_ALLOWLIST` is enforced by a host-side HTTP CONNECT/absolute-form proxy injected via standard `HTTP_PROXY`/`HTTPS_PROXY` env (per sandbox; `tests/unit/test_netfilter.py`). Raw sockets that ignore the proxy env and speak directly to numeric IPs are **not** filtered — that would need firewall-level rules inside Docker.
* **Desktop control** (pyautogui) is opt-in; unit tests cover action dispatch against a fake GUI and the real-screen test skips gracefully where no interactive desktop exists (`tests/unit/test_desktop_control.py`), but it is still not exercised in CI.
* **Frontend:** the Library, Scheduled and Projects nav items have no backend features (out of the spec's scope). xterm.js loads from a CDN.
* **Electron:** the GUI window itself has not been verified in an interactive session from the automation shell (backend lifecycle, packaging and resources are verified — see [E2E_REPORT.md](E2E_REPORT.md)); auto-update stays idle until a GitHub release is published. On machines where Chromium's sandbox broker aborts pre-main, the installed shortcuts pass `--no-sandbox` (see `build/installer.nsh`) — renderer isolation is off on such installs.
* **Packaged build excludes the Laya real-weights stack** (torch/transformers/laya) to keep the install near 850 MB: the Rules engine governs and Laya reports unavailable. Source-checkout runs keep full Laya shadow-mode support, and the packaged exclusion is dropped automatically if `--collect-all` is restored in `packaging/build_backend.py`.
* **Not finished:** nothing currently tracked — the previous gaps (README quickstart, E2E report, durable event replay, concurrent-run workspace isolation) are closed; see the items above for what remains open.
